From documents to intelligence — built your way.

An open-source, API-first knowledge extraction engine that converts any financial document format into queryable knowledge graphs.

Financial analysts dedicate hours reading reports to understand the causal relationships driving revenue, risk, and growth. MarketFoundry treats unstructured text as a first-class data source, automatically building custom knowledge graphs that answer "Why did Q3 miss?" or "What caused churn?" with evidence from across your entire document corpus.

Built for data engineers, quantitative analysts, and fintech teams building Retrieval-Augmented Generation (RAG) systems, analytics dashboards, and document intelligence pipelines.

The Problem We Solve

The Challenge

Traditional analysts spend hours manually reading through filings, transcripts, and reports to piece together what's driving revenue, risk, and growth. It's slow, it doesn't scale, and it keeps valuable context out of the tools that actually make decisions.

The firms building the next generation of financial analytics know that unstructured text can't stay unstructured. They're building RAG systems, analyst dashboards, and data pipelines — but without structured extraction upstream, documents still go in as raw text and insight still has to come out through manual effort.

Market Foundry changes that. Open-source and API-first, we give data-driven teams the extraction layer their pipelines are missing — so the narrative behind the numbers becomes just as queryable as the numbers themselves.

Document-aware extraction, built for modern financial pipelines

Market Foundry classifies each document, sections it intelligently, and routes it to specialized schemas that extract entities, relationships, and where present, causal structure. The result is a unified knowledge graph your existing tools can actually work with.

Same RAG system, sharper retrieval. Same dashboard, richer context. Built open-source so you can integrate it, extend it, and make it your own.

System Scope

What The System Does

  • Document-type classification (5 types)
  • Dynamic topic sectioning & YAML schema generation
  • Schema-guided triple extraction via OneKE
  • Neo4j knowledge graph construction
  • Multi-format ingestion (PDF, DOCX, HTML, JSON)

What The System Doesn't Do

  • Query UI or chat interface
  • Real-time or streaming data feeds
  • Post-hoc ontology normalization
  • Cross-document co-reference resolution at scale

How It Works

MarketFoundry uses a document-aware pipeline that intelligently processes each financial document type to extract the most valuable causal relationships.

1

Document Ingestion

Upload PDF, DOCX, HTML, or JSON files. Market Foundry handles any financial document format; earnings calls, SEC filings, press releases, research reports, and news articles.

2

Document Classification

An ensemble ML model automatically detects document type and routes it to the appropriate extraction schema. No manual configuration needed.

3

Intelligent Sectioning

LLMs extract topics dynamically and auto-generate YAML templates tailored to each section, preserving the context that generic text chunking would lose.

4

Schema Routing

Each section is matched to a specialized extraction schema based on its topic, ensuring the right relationships get captured for the right content.

5

Extraction

OneKE (a schema-guided knowledge extraction framework) + Qwen2.5-7B extracts structured triples: subject, predicate, object, with source citations so every insight is traceable back to its document.

6

Knowledge Graph

All triples are stored in Neo4j, creating a unified graph across your entire document corpus. Query it directly, plug it into your RAG system, or pipe it into your analytics stack.

What We Built vs. What We Used

Original Work (Built by Our Team)

  • Ensemble document classifier (TF-IDF logistic regression + KNN)
  • Dynamic topic extraction and multi-perspective YAML schema generation
  • Document-type-aware pipeline routing logic
  • Engineering robustness layer: JSON validation, fallback schemas, edge-case handling
  • Incremental result persistence and reproducibility tooling

Third-Party Tools (Integrated and Extended)

  • OneKE, base schema-guided extraction framework (Luo et al., 2025)
  • Qwen2.5-7B and Meta-Llama, open-source LLM inference
  • Neo4j, graph database and storage layer
  • SentenceTransformers, semantic embeddings for the k-NN classifier

Limitations

Schema Fragmentation

Open-schema design produced 423 distinct relationship types across 15 documents, reducing cross-document comparability without additional ontology normalization.

Sparse Graph Connectivity

Average node degree of ~1.64 means most entities participate in only 1–2 relationships, limiting multi-hop reasoning without further graph enrichment.

Long-Document Instability

Dynamic YAML generation succeeded for 47.3% of documents; long regulatory filings and earnings call transcripts triggered context-window saturation more frequently.

Compute Constraints

Evaluated on 1–4B parameter open-source models. Larger models would likely improve coreference resolution, relation naming consistency, and extraction depth.

LLM Hallucination Risk

Schema-guided prompting significantly reduces hallucinated relations, but cannot eliminate them entirely. The Reflection Agent was observed renaming relation labels to semantically similar alternatives outside the defined schema, introducing subtle inconsistencies even when outputs appear structurally valid.

Next Steps

Market Foundry's intelligence layer plugs directly into existing RAG pipelines, analyst dashboards, and causal inference workflows without replacing them. Same retrieval system, sharper context. Next steps include stronger schema constraint enforcement, corpus expansion, and two-stage extraction strategies to improve robustness on long-form documents without requiring larger models.
